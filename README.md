## Responsibilities of this repository

`ai-eval-service` is OpenStrata's **Evaluation Service** (ai-native domain), the engineering
bearer of the "Evaluation Phase (§6.3)" and "MLOps and Evaluation Layer (§4.6)". It converges
external evaluation frameworks (Promptfoo / DeepEval / Ragas) into orchestratable, replaceable
evaluation capabilities via the platform `Eval` SPI (`bom.yaml Eval = 1.0.0`).

- **Promised capabilities (R1–R8):** dataset/case management, run arrangement/execution,
  pluggable metric scoring, result aggregation & reporting (with regression comparison),
  and PII/security handling (reusing the platform risk-control port).
- **Domain aggregate roots:** `EvalDataset`, `EvalRun`, `EvalReport` (pure logic, zero deps).
- **SPI ports (domain-defined, infra-implemented):** `AgentRuntimePort` (run the evaluated
  Agent), `ScorerPort` (pluggable scorers), `EvalRepositoryPort` (persistence),
  `LLMProviderPort` (synthetic data gen), plus integration ports `Cache/Auth/Tracing/VectorStore`.
- **Adapters (ACL anti-corrosion):** in-memory fakes + heuristic scorers for offline; lazy
  real adapters for `ai-gateway-core` (AgentRuntime/LLM), Redis (Cache), Keycloak (Auth),
  Langfuse/OTel (Tracing), Qdrant (VectorStore), and PostgreSQL (SQLAlchemy repository).
- **External components (default ✅ / optional):** FastAPI + Pydantic v2 ✅, SQLAlchemy +
  PostgreSQL ✅, Redis ✅; Promptfoo ✅ (core), DeepEval/Ragas ❌ (optional, lit on demand).

## Local development

```bash
# Create a venv and install runtime + dev deps (Python 3.11+)
python3 -m venv .venv && .venv/bin/pip install fastapi uvicorn pydantic sqlalchemy pyyaml opentelemetry-api pytest httpx

# Run the offline test suite (in-memory repo + fake adapters, no Postgres/Redis/LLM)
.venv/bin/python -m pytest -q

# Run the service (defaults to an offline "memory" container)
.venv/bin/python -m ai_eval_service.main        # or: uvicorn ai_eval_service.main:app
```

The service defaults to an offline `memory` DI mode (in-memory repository, fake Agent/LLM,
heuristic scorers) so it runs and is testable without any external dependency. Switch to
production wiring with `build_container(mode="production")` (requires `PGDSN` and the
SPI endpoints). See `docs/ARCH.md` §5 and `docs/DESIGN.md` §4–§7.

### Quickstart

```bash
curl -X POST localhost:8000/v1/datasets -H 'content-type: application/json' \
  -d '{"name":"qa","dataset_id":"qa-golden"}'
# -> { "dataset_id": "qa-golden", "version": "v1", ... }

curl -X POST "localhost:8000/v1/datasets/qa-golden/cases?version=v1" \
  -H 'content-type: application/json' \
  -d '{"inputs":{"query":"hi"},"expected":{"answer":"hi"}}'

curl -X POST localhost:8000/v1/runs -H 'content-type: application/json' -d '{
  "dataset_id":"qa-golden","dataset_version":"v1",
  "agent":{"agent_id":"cs","tenant_id":"t"},
  "scorer_set":["promptfoo_accuracy"]}'
# -> { "run_id": "...", "status": "done", ... }
```
